我在博客里藏了一个 2015 年的大学论坛

最近在做一件不太正经的事：写一个网页解谜游戏。

没有引擎，没有后端，没有数据库。就是几个 HTML 文件，扔在静态站里。

它是什么

故事发生在一所虚构的大学——江临大学。玩家会拿到一台”网页时光机”，输入一个地址，看到的是这所学校 2015 年的 BBS 存档。

论坛里什么都有：置顶公告、灌水帖、求资源的、失恋的、骂教务处的。你可以点开任何一个帖子，看正文，看回复，点进楼主的个人主页，看看他 2015 年都在干什么。

然后你会发现，有些帖子不太对劲。

为什么是论坛

因为论坛的”旧”本身就是叙事。

版块列表、在线人数、今日发帖、页脚的备案号、签名档里的颜文字、233、火钳刘明、mark 一下——这些东西现在看起来很土，但它们是真实的。2015 年的中文互联网就长这样。

我想还原的是那种感觉：一个没人维护的旧站点，页面加载很慢，图标是 GIF，背景是平铺的格子。你点进去，会觉得”这里不该还有人在”。

为了不像”现代网页套了个复古皮肤”，细节都是一个个抠的：帖子列表的行高、版块的图标、用户组颜色、甚至”最后回复”那一列的时间格式。

技术上怎么做的

纯前端。 所有内容硬编码在 JS 里，不联网，不请求任何接口。

  • 多个 HTML 页面 + hash 路由，在首页、版块、帖子、用户主页之间切换
  • 本地搜索：输入预设关键词，返回预设好的帖子和回复，搜不到就显示”没有找到相关帖子”
  • 论坛里所有东西都能点：帖子、用户名、版块、图片（可放大）
  • 右键不是被禁用，而是被做成了一条隐藏的解谜线——你越想看源码，看到的提示越多

第二条是我最满意的设计。大部分解密游戏会粗暴地 document.oncontextmenu = () => false，但那既挡不住人，也很难看。我反过来做：右键会让你看到一些”不该出现在源码里”的东西，而这些东西本身就是线索。

结构

按短篇小说的体量规划，总共约十万字，分多章。

第一章是三个页面：剧情引入 → 网页时光机 → 论坛。后面的每一章是两个页面：剧情推进，然后是论坛的另一个时间点。

目前第一章的原型已经能跑通，1500 行左右，从输入地址到翻完整个版块，闭环是通的。

两个难的地方

一是提示不能写得太”聪明”。

AI 写的提示有个固定腔调：请输入关键词，例如：江临。这种一眼假。真实的旧论坛不会给你提示，它只会让你自己瞎点。所以我把引导全部藏在界面里——一个错位的图标、一条不该存在的回复、一个时间对不上的帖子。

二是假数据要像真的。

玩家一旦觉得”这是编的”，沉浸感就没了。所以得有大量和主线无关的日常帖：有人在问选课，有人在出二手自行车，有人在深夜发一句没头没尾的话。这些帖子没有任何用处，但它们让论坛活了起来。

进度和下一步

  • 第一章原型：能跑，正在补内容
  • 剩下的章节：先写大纲，再逐章实现
  • 还没做的：存档/进度、多结局、移动端适配

做完之后入口会放在博客里，可能藏得比较深。到时候会单独发一篇说明。

一句声明

故事纯属虚构。 江临大学、BBS 里的所有用户、帖子、事件，都是编的，与任何真实的学校、网站、个人无关。

如果你对这个东西感兴趣，或者想帮忙测试（尤其是”能不能被卡住”这件事），可以来 X 找我。
