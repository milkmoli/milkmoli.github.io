把主题配置从 node_modules 里救出来

先说一个我差点踩中的坑：主题的导航栏、配色、歌单，我都是在 node_modules/hexo-theme-redefine/_config.yml 里改的。直到某天准备重装依赖，我才意识到——这个文件在 node_modules 里，而 node_modules 是可以随时被删掉重建的目录。

也就是说，一次 rm -rf node_modules && npm install，或者主题升个小版本，我辛苦调的 500 多行配置会全部回到默认值。

这篇就把这件事彻底解决，顺便讲清楚 Hexo 的配置到底是怎么一层层加载的。

📦 问题：为什么不能直接改主题目录

Hexo 的主题是通过 npm 安装的（hexo-theme-redefine），它和你写的文章、站点配置在同一个文件夹里，但地位完全不同：

  • source/、_config.yml：你的资产，进 git，进备份
  • node_modules/：依赖产物，不进 git，随时可重建

把配置写在依赖目录里，等于把笔记写在了别人的草稿纸上。

🔍 原理：Hexo 的配置加载顺序

Hexo 启动时会按顺序读配置，后面的覆盖前面的：

  1. _config.yml（站点配置，在你的仓库里）
  2. node_modules/hexo-theme-redefine/_config.yml（主题自带默认值）
  3. _config.redefine.yml（根目录，主题配置覆盖层）← Hexo 5 之后支持
  4. _config.yml 里的 theme_config: 字段（临时覆盖）

第三步：加进版本管理

_config.redefine.yml 放在仓库根目录，天然会被 git 跟踪。这一步最关键——它现在和你的文章一样，有历史、有备份、能回滚。

⚠️ 两个容易翻车的细节

1. 深度合并，但数组是整体替换

deepMerge 的行为是：对象一层层递归合并，数组直接替换。所以改 navbar.links、aplayer.audios 这类数组时，写的是”完整列表”，不是”追加一项”。

2. 主题升级后，新增的配置项不会自动出现

比如主题从 2.8 升到 2.9，默认配置里多了几个开关。你的副本还是旧的，新功能可能静默失效。

📝 小结

文件 职责 能不能改
_config.yml 站点：标题、域名、部署 ✅ 你改
node_modules/.../_config.yml 主题默认值 ❌ 只读基线
_config.redefine.yml 主题：导航、配色、插件 ✅ 你改
theme_config:（写在站点配置里） 临时单点覆盖 偶尔用

一句话：配置要跟着代码走，不能跟着依赖走。
